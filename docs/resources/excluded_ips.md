# qualys_excluded_ips (Resource)

Excludes IPs from Qualys scanning
(`/api/2.0/fo/asset/excluded_ip/` — Confirmed: this repository's discovery
notes, doc 03 §1, confirm the `list`/`add`/`remove`/`remove_all` actions and
their request parameters).

## Write-only with respect to drift

This resource does not read back what Qualys currently has excluded. The
excluded-IP list endpoint's response shape (its XML element names) is not
documented anywhere this provider's research could evidence — only the
request parameters and the fact that a `list` action exists — so, rather than
guess response field names, `qualys_excluded_ips` reconciles by re-issuing
`add`/`remove` for whatever changes between plans, idempotently, treating
Terraform state as authoritative. A change made outside Terraform (someone
re-including an IP via the UI, for example) is not detected until the next
apply overwrites it back to the configured set.

## Example Usage

```terraform
resource "qualys_excluded_ips" "maintenance_window" {
  ips     = ["10.40.5.10", "10.40.5.0/28"]
  comment = "Under active maintenance; exclude from scanning"

  # Automatically re-include these IPs in scanning after 14 days, in case
  # the exclusion is forgotten.
  expiry_days = 14
}
```

## Schema

### Required

- **ips** (Set of String) IPs, hyphenated ranges or CIDR blocks to exclude from scanning. Managed authoritatively.

### Optional

- **asset_group_names** (Set of String) Scope the exclusion to these asset groups.
- **comment** (String)
- **expiry_days** (Number) Automatically re-include the IPs in scanning after this many days. Zero (the default) leaves the exclusion open-ended.
- **id** (String) The ID of this resource.
- **network_id** (String) Network to scope the exclusion to. Changing it forces replacement.
